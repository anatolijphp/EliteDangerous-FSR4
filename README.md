# ED-FSR — FSR 4 / FSR 3.1 and Frame Generation for Elite Dangerous

A drop-in mod that replaces Elite Dangerous' built-in **AMD FSR 1** upscaler with **AMD FSR 4 (ML)** or **FSR 3.1**
temporal upscaling, and adds **AMD FSR Frame Generation**. The mod comes with an in-game settings panel styled to match
the game's HUD.

> Unofficial fan project. Not affiliated with or endorsed by Frontier Developments or AMD.
> It modifies rendering only, with no gameplay or memory changes. Use at your own risk.

## Features

- **FSR 4 (ML)** on RDNA 4 GPUs (Radeon RX 9000), **FSR 3.1** on other GPUs. You can switch between them at runtime.
- **Temporal upscaling inputs generated by the mod.** Elite Dangerous has no TAA and no motion vectors. The mod adds
  sub-pixel camera jitter and rebuilds camera motion vectors from the depth buffer and the game's camera matrices.
  The cockpit is excluded from motion.
- **Reactive mask for HUD and transparents.** The mod snapshots the scene before transparent and HUD rendering and
  derives a reactive mask from that snapshot. This reduces ghosting on holograms, particles, engine glow and the HUD.
- **FSR Frame Generation (FSR FG 4 on RDNA 4).** The mod presents through an AMD FidelityFX frame-generation swapchain
  (D3D12), bridged from the game's D3D11 renderer. You can toggle it at any time.
- **Quality modes.** You can choose Ultra Quality, Quality, Balanced, Performance, Ultra Performance (33%) or
  Native AA, or keep the game's own setting.
- **In-game overlay in the game's HUD style.** A hint appears at startup. **CTRL+F8** opens the settings panel, which
  also shows live status: render and output resolution, upscaler and frame generation versions, and FPS.
- **Safe fallback.** If anything fails to initialise, the game's original FSR 1 path is used.

## Requirements

- Elite Dangerous (Horizons 4.0 / Odyssey client, DirectX 11), Windows 10/11.
- A GPU with DirectX 12 support. FSR 4 needs an AMD RDNA 4 GPU and a recent Adrenalin driver.
- In-game settings:
  - **Upscaling = FSR.** The game's *Supersampling* setting picks the render scale.
  - **Anti-aliasing = Off** (recommended).
  - **Borderless window mode**, if you use frame generation.

## Installation

### Installer (recommended)

1. Download `ED-FSR-Setup-<version>.exe` from **Releases**, or the `ed-fsr-installer` artifact of a CI run.
2. Close the game and run the installer. It detects the game folder (Epic, Steam or the Frontier launcher). Check it
   or browse to the folder that contains `EliteDangerous64.exe`, e.g.
   `...\EliteDangerous\Products\elite-dangerous-odyssey-64`.
3. Start the game. The "ED-FSR" hint appears in the top-right corner. In game: **Upscaling = FSR**, **Borderless
   window** for frame generation, and press **CTRL+F8** for settings.

If the game folder already has a `dinput8.dll` from another mod, the installer warns you, backs it up as
`dinput8.dll.edfsr-backup` and restores it on uninstall. Uninstall from **Settings > Apps** ("ED-FSR"). This removes
`dinput8.dll` and the `edfsr` folder, including settings and logs, and leaves the game's own files alone.

### Manual install

1. Download the `ed-fsr-<version>.zip` from **Releases**, or the `ed-fsr` artifact of a CI run, and unpack it.
2. Close the game. Run `install.ps1 -GameDir <folder containing EliteDangerous64.exe>`. The default is
   `D:\Epic Games\EliteDangerous\Products\elite-dangerous-odyssey-64`. You can also copy the files yourself:
   `dinput8.dll` and the `edfsr` folder go into the game folder.
3. Start the game and press **CTRL+F8** to configure.

To uninstall, run `install.ps1 -Uninstall` (with the same `-GameDir`), or delete `dinput8.dll` and the `edfsr` folder
from the game folder.

### Installed files

## Settings

Open the panel with **CTRL+F8** (ESC closes it). While the panel is open, the game does not receive mouse or keyboard
input, and frame generation is paused. **SAVE** writes `edfsr\edfsr.ini`.

| Panel | ini key | Values | Applies |
|---|---|---|---|
| Upscaler | `upscaler` | `fsr4`, `fsr31`, `game` (the game's FSR 1) | live |
| Sharpness | `sharpness` | 0–1 (FSR sharpening; the game's own sharpening still runs) | live |
| Quality mode | `quality_mode` | `game`, `ultra_quality`, `quality`, `balanced`, `performance`, `ultra_performance`, `native` | on game start ¹ |
| Frame generation | `framegen` | 0 / 1 (initial state) | live |
| Advanced: camera jitter | `jitter` | 0 / 1 | live |
| Advanced: motion vectors | `motion_vectors` | 0 / 1 | live |
| Advanced: cockpit depth | `cockpit_depth` | pixels closer than this count as cockpit (no motion) | live |
| Advanced: HUD / transparency mask | `reactive_mask`, `reactive_scale` | 0 / 1, strength 0–2 | live |
| Advanced: FSR debug view | `debug_view` | 0 / 1 | live |
| — | `framegen_swapchain` | 1 (default) routes presents through the FG swapchain. 0 disables frame generation entirely | on game start |
| — | `enabled` | 0 turns the whole mod off | on game start |

¹ The render resolution belongs to the game. The mod writes the matching *Supersampling* value into the game's
graphics config before the game starts. For a live change, use the game's own **Options > Graphics > Supersampling**.
The mod follows the new resolution automatically.

## Known limitations

- **Moving objects.** Other ships and SRVs have no per-object motion vectors yet. The reactive mask and FSR's own
  heuristics limit the ghosting, but fast-moving objects can still trail.
- **Frame generation needs a borderless window.** Exclusive fullscreen requests are ignored while the FG swapchain is
  active.
- **VR is not supported.**
- **Uninstalling does not reset the render scale** the mod wrote to the game's graphics config. The original file is
  kept as `Custom.4.4.fxcfg.edfsr-backup` next to it, in
  `%LOCALAPPDATA%\Frontier Developments\Elite Dangerous\Options\Graphics`.
- **VPN adapters such as Radmin VPN** can make Elite Dangerous fail to connect to its servers (unrelated to this
  mod). Disable them while playing.

## How it works

- **Loading.** `dinput8.dll` is a proxy for the system DirectInput DLL. It hooks D3D11 device creation and selected
  context methods: `CSSetShader`, the CS SRV/UAV setters, `OMSetRenderTargets` and `RSSetViewports`.
- **Replacing EASU.** The game's FSR 1 EASU compute shader is identified by a hash of its bytecode and swapped for a
  no-op. Before the following RCAS pass, the mod copies color, depth and motion vectors to textures shared with
  D3D12. It then runs `ffxDispatch` (AMD FidelityFX SDK 2.4) and writes the result back into the game's upscaled
  texture.
- **Jitter.** Jitter is applied as a sub-pixel viewport offset while the scene depth buffer is bound. Motion vectors
  come from depth plus the per-frame camera constant buffer.
- **Frame generation.** The game's swapchain is redirected to a hidden window. Every `Present` hands the frame to an
  FFX frame-interpolation proxy swapchain on the real window.
- **Reactive mask.** The first transparent-geometry shader (identified by bytecode hash) triggers a copy of the HDR
  scene target. Before upscaling, the relative difference between the final HDR image and that copy becomes the
  `reactive` input of FSR.
- **Overlay.** The settings overlay uses Dear ImGui. It deliberately avoids `SwapDeviceContextState`, because the D3D11
  runtime rewrites the context vtable on every state swap and would remove the mod's hooks.

## Building

The build uses the [llvm-mingw](https://github.com/mstorsjo/llvm-mingw) toolchain, the
[AMD FidelityFX SDK 2.4](https://github.com/GPUOpen-LibrariesAndSDKs/FidelityFX-SDK), [Dear ImGui 1.91.8](https://github.com/ocornut/imgui)
and `renderdoc_app.h`:

```sh
LLVM_MINGW=... FFX_SDK=... IMGUI_DIR=... RENDERDOC_INC=... sh build.sh   # -> build/dinput8.dll
```

GitHub Actions (`.github/workflows/build.yml`) downloads all dependencies and builds on every push. It produces the `ed-fsr` package and
the `ed-fsr-installer` artifact (Inno Setup script: `installer/edfsr.iss`). Tags `v*` publish a release with both the
installer and the zip.
